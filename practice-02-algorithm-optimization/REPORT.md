## 1. Исходный алгоритм

Исходная функция `FindDuplicates` перебирает каждую пару элементов вложенными циклами. При совпадении она дополнительно вызывает `duplicates.Contains`, чтобы не добавить одно значение повторно.

Для массива длины `n` два цикла дают примерно `n(n - 1) / 2` сравнений:

```text
T_old(n) = Θ(n²)
```

Память для результата и списка уже найденных дубликатов — `O(n)`. Вызов `List.Contains` добавляет лишний линейный поиск среди уже найденных значений.

## 2. Новый алгоритм

В `DuplicateFinder.FindDuplicates` используются два хеш-множества:

- `seenValues` сообщает, встречалось ли значение раньше;
- `reportedDuplicates` гарантирует, что значение попадёт в результат только один раз.

Массив просматривается один раз. При втором появлении значения оно добавляется в результат, поэтому порядок дубликатов совпадает с исходной функцией — по моменту второго появления.

Для `HashSet<int>` поиск и добавление выполняются за `O(1)` в среднем:

```text
T_new(n) = O(n) в среднем
S_new(n) = O(n)
```

В худшем случае при патологических коллизиях хеш-таблицы оценка времени может ухудшиться, но для обычных `int` это не является практическим сценарием.

## 3. Сохранение корректности

В benchmark-программу добавлены проверки следующих случаев:

- пустой массив;
- массив без дубликатов;
- повторяющиеся значения;
- отрицательные и нулевые значения;
- одно значение, повторённое несколько раз.

Во всех случаях результат нового алгоритма сравнивается с результатом исходного. Для демонстрационного массива `{ 1, 2, 3, 2, 4, 5, 5, 6 }` обе версии возвращают одинаковый результат:

```text
Дубликаты: 2, 5
```

Измерение времени в демонстрационном `Main` также сохранено; меняется только фактическое время работы поиска.

## 4. Замеры производительности

Замеры выполнены на детерминированных массивах, где каждое значение встречается дважды. Для каждого размера выполнены две прогревочные итерации и семь измерений; в таблицу попало медианное время. `results_equal=True` означает, что результаты алгоритмов совпали.

| N | Исходный, мс | Новый, мс | Ускорение | Результаты равны |
|---:|---:|---:|---:|:---:|
| 1 000 | 1.247 | 0.108 | 11.5× | да |
| 3 000 | 11.094 | 0.249 | 44.5× | да |
| 6 000 | 44.538 | 0.181 | 246.1× | да |
| 12 000 | 177.225 | 0.183 | 970.2× | да |
| 24 000 | 706.564 | 0.431 | 1639.3× | да |

Сырые данные находятся в [`verification/benchmark.csv`](verification/benchmark.csv). При небольших `N` время нового алгоритма близко к накладным расходам таймера и выделения памяти, поэтому оно не обязано монотонно расти на каждой отдельной точке. При этом время исходного алгоритма увеличивается примерно в четыре раза при каждом удвоении `N`, что соответствует `O(n²)`, а новый алгоритм сохраняет порядок величины `O(n)`.
